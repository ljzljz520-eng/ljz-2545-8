设计说明

原创视觉、对象模型与交互取舍一并交付。

一、领域模型：为什么不能给整座桥一个布尔值

系统中有三类独立对象：桥梁本体（bridge：结构、材质、保护提示）、入口（entrance：门、闸口、开闭时间）、通行段（edge：引道、桥面穿越段、步道、跨区联络线）。维护日历挂在通行段上。

  • 一端入口关闭或引道维护 → 该端桥头与从该端出发的穿越不可行；
  • 但另一端入口、另一端观景点继续独立求值——“不能过桥”不等于“不能看桥”；
  • 桥面穿越必须真正走上 crossing 段；两岸山路绕行可达时，结论是“可绕行、不计为穿越古桥”；
  • 故事页 API 不输出 open: true/false，状态在 ends[] / crossing / views[] 上分别给出。

二、规划：明确数据约束

  • 净宽 < 1.20m 或坡度 > 15% 的实测段，亲子方案标记为实测阻断；
  • 任一字段为 null（未测）→ 无法确认，绝不臆断；
  • 系统永不自动输出“适合儿童/无障碍(accessible)”认证；轮椅可达需要现场实测，本工程不替代；
  • 锁定停留点不可达 → 整体 infeasible + 关键阻断解释，不静默改点；未锁定点不可达 → 跳过并局部更新；
  • 预制主题路线不预存路径，每次按当日状态逐段求值；与按图搜索同数据对比。

三、离线包：版本清单 + 分块校验

  • manifest 声明每个版本的类型（full/delta）、父版本、块清单与 SHA-256；
  • 块状态机：missing → verified / corrupt；全部 verified 才能 usable；
  • 目标版本 ≤ 已装版本 → 409 stale_rollback（旧包回灌拒绝）；增量父版本不匹配 → delta_base_mismatch。

四、原创视觉

石拱桥：券脸石纹理、拱背隆起桥面、古樟与溪面倒影。

木拱廊桥：九开间廊柱、瓦垄、木拱与潭水。

色板：溪岩苔绿 #274039（主色）、券脸石黄 #D9B45C（强调）、夯纸米 #F7F1E3（底）、警示朱 #B5462F、通行青 #3E7C6A。标题用中文衬线呼应碑刻气质，正文用系统无衬线保证可读性；状态用语义色+文字双编码，不只靠颜色区分。

五、不编造承载保证

所有桥梁、题记与维护记录均为虚构；桥面数据（跨径、净宽、坡度）仅用于演示路径约束演算，不是勘察结论，也不构成承重或通行安全承诺。真实出行请以文物管理部门现场告示与专业评估为准。

千溪古桥徒步 · 教学/演示项目。对象模型：桥梁本体 ≠ 入口 ≠ 通行段；状态精确到端、到段。

宽度或坡度未测一律显示“无法确认”；不自动认证适合儿童或无障碍；不编造真实桥梁承载保证。
